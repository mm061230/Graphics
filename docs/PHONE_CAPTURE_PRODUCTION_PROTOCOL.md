# Phone Capture Production Protocol

## 1. Real Requirement

用户实际工作方式：

```text
用户用手机拍机械制图题
  ↓
系统识别题目要求
  ↓
系统提取图像几何数据、比例、投影对应关系
  ↓
系统完成补线/剖视/断面/标准答案图
  ↓
系统输出高质量 PNG/SVG/DXF/PDF 和审计报告
```

该需求不依赖预置回归题库。回归题库不是启动前提，而是后续生产稳定性的质量资产。

## 2. Non-Negotiable Truth

手机拍题可以做，但不能允许系统在以下情况中假装确定：

- 题目文字缺失或模糊。
- 剖切箭头、A-A/B-B 标记不清。
- 已知视图被裁掉。
- 虚线、中心线、剖面线被压缩或糊成一团。
- 单张图缺少足够视图，隐藏结构存在多解。

生产系统必须遵守：

```text
看不清就不脑补。
多解就请求最小确认。
确认后再进入最终出图。
```

完美输出的前提不是“AI 神猜”，而是：

```text
输入可读 + 几何可提取 + 投影可闭合 + 剖切规则可判定 + 门禁可通过
```

## 3. Revised First-Version Strategy

第一版不要求已有回归题库，而是采用“逐题严格生产”模式：

```text
每张手机照片
  ↓
质量审计
  ↓
自动校正
  ↓
题意识别
  ↓
几何候选提取
  ↓
比例和投影关系闭合
  ↓
低置信项最小确认
  ↓
CAD 确定性出图
  ↓
硬门禁审计
  ↓
最终交付
```

其中“低置信项最小确认”不是让用户做我的工作，而是在题意或隐藏结构客观多解时，必须让用户确认一个关键事实。例如：

```text
检测到 A-A 剖切箭头不清。请确认剖切方向是向左还是向右。
```

## 4. Phone Image Intake Gate

系统收到照片后，先输出输入质量报告：

| Check | Pass Requirement |
|---|---|
| 分辨率 | 单题有效区域宽度建议 >= 1200 px |
| 倾角 | 可校正，优先 <= 8 deg |
| 透视 | 四边界或主要水平/垂直线可估计 |
| 对比度 | 图线和纸面可分离 |
| 文字 | 题目要求可读 |
| 关键符号 | 剖切符号、箭头、中心线、虚线可辨 |

通过：继续处理。

部分通过：进入半自动确认。

失败：输出重拍建议，不进入最终答案生成。

## 5. Extraction Pipeline

### 5.1 Image Correction

使用 OpenCV：

- 文档边缘/题框检测。
- 透视校正。
- 旋转校正。
- 自适应阈值。
- 去噪与线条增强。
- 单题裁切。

输出：

- 原图备份。
- 校正图。
- 增强图。
- 输入质量 JSON。

### 5.2 Requirement Recognition

使用视觉模型/OCR/规则结合：

- 题号。
- 题型：补线、全剖、半剖、局部剖、旋转剖、阶梯剖、断面图。
- 目标视图：主视、俯视、左视、A-A/B-B 剖视。
- 剖切方向。
- 是否要求补全漏线。

AI 只允许输出结构化结果：

```json
{
  "problem_id": "unknown",
  "task_type": "HALF_SECTION",
  "target_view": "LEFT",
  "section_label": "A-A",
  "confidence": 0.86,
  "uncertain_fields": []
}
```

### 5.3 Geometry Extraction

使用 OpenCV + 几何规则：

- Hough 直线检测。
- Hough 圆检测。
- 轮廓检测。
- 圆弧拟合。
- 虚线/中心线模式识别。
- 视图 bounding box 分割。
- 坐标归一化到标准画布。

所有候选图元带置信度，不直接进入最终图：

```json
{
  "id": "LINE_CAND_001",
  "type": "LINE",
  "coords": [120.5, 300.0, 480.0, 300.3],
  "line_style_guess": "VISIBLE_OUTLINE",
  "source": "opencv_candidate",
  "confidence": 0.91
}
```

## 6. Ratio and Projection Closure

照片会变形，所以不能信任原始像素距离。必须先建立校正坐标系，再做比例闭合。

系统必须建立：

- 页面坐标系。
- 题目局部坐标系。
- 每个视图局部坐标系。
- 主视图中心锚点。
- 俯视图中心锚点。
- 左视图中心锚点。

然后执行：

```text
主-俯：长对正
主-左：高平齐
俯-左：宽相等
同轴圆：圆心一致
对称结构：两侧距离一致
槽/孔：宽度、半径、中心距闭合
```

照片比例修正原则：

```text
整体透视校正后，所有视图共享同一比例。
如果局部拍摄变形严重，不允许强行出最终答案，必须标记低置信或要求重拍。
```

## 7. Ambiguity Handling

若系统能从图中严格推导，则自动继续。

若存在多个合法解，则不得猜测。

最小确认问题最多一次问 1 到 3 个，且必须是关键事实：

- 剖切方向。
- 题型要求。
- 哪个视图是目标空白图。
- 某条模糊虚线是否存在。
- 原图是否有被裁掉部分。

确认后写入：

```text
work/review_marks/
```

并成为审计报告的一部分。

## 8. Final Output Is Deterministic

最终图不能由 ChatGPT Images、GPT Image、Stable Diffusion 或任何随机图像模型生成。

最终图必须由：

- geometry JSON
- ezdxf
- svg renderer
- Shapely topology
- pytest gates

确定性生成。

AI 可以做：

- 读题。
- 解释。
- 候选图元生成。
- 多解提醒。
- 作图步骤说明。

AI 不可以做：

- 直接生成最终答案图片。
- 自己宣布门禁通过。
- 在看不清时脑补关键结构。

## 9. No Initial Regression Dataset Plan

没有回归题库时，采用增量生产策略：

```text
第 1 张题：人工严格复核，形成样例
第 2-20 张题：建立常见题型模板和失败样例
第 20-50 张题：沉淀测试 fixtures
第 50+ 张题：形成小型真实回归集
```

每完成一题，保留：

- 原图。
- 校正图。
- 几何 JSON。
- 最终 SVG/DXF/PDF/PNG。
- 审计报告。
- 失败与修正记录。

这不是额外负担，而是系统越用越稳的办法。

## 10. Production Promise Boundary

可以承诺：

- 对清晰、完整、可读的手机拍题，按严格流程提取题意和几何关系。
- 对可闭合的机械制图题，输出标准 CAD 风格答案。
- 对不确定处主动拦截，不胡画。
- 所有最终输出可复核、可追溯。

不能承诺：

- 任意模糊、缺角、反光、遮挡照片都完美识别。
- 题目缺失关键信息时仍自动唯一解。
- 不经过几何门禁就输出所谓完美答案。

最终生产定义：

```text
不是每张照片都盲目出图，
而是每张照片都得到正确处理：
能确定则完美出图，
不能确定则精准指出缺失信息并请求最小确认。
```
